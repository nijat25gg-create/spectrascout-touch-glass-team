# Тестовые кейсы и разметка

Три источника кейсов, один файл `test-cases-template.csv` (колонки повторяют бывший `cases/_template.yaml`: метод 1 и 2, отклонённые, вопросы, источник).

| source_type | Откуда | split | Сколько |
|---|---|---|---|
| `afs` | 8 сценариев AFS (получим 16.10) | `test` | 8 |
| `internet` | application notes производителей, статьи по PAT/inline-спектроскопии, кейсы с сайта AFS | `dev` | 20–25 |
| `expert` | случаи из интервью 5 химиков, без имён | `dev` | 5–10 |
| `edge` | придуманные ловушки: нужен MS/NMR, ATEX, флуоресценция, почти нет данных | `dev` | 5 |

**Правило:** веса и правила подбираем только на `dev`. На `test` (8 сценариев AFS) только меряем. Так цифры в видео честные.

## Кто размечает

1. **Гаджи** ищет кейсы в интернете (можно с Claude) и заносит: `customer_text` своими словами в стиле письма клиента, `source_ref` = ссылка, `split=dev`.
2. **Ярик** ставит черновую разметку: `expected_top1_method`, `expected_top2_method`, `expected_rejected_with_reason`, `must_ask_questions`. В кейсах из интернета метод обычно прямо указан в источнике, его и берём.
3. **Никита** только проверяет: `chemist_verified_yes_no` + одна строка в `chemist_notes`, если не согласен. Пачками по 10, около 5 минут на кейс.
4. Спор: финальное слово за Никитой.

Каждый кейс в двух вариантах: `full` (всё есть) и `gaps` (не хватает данных), чтобы проверять и вопросы.
